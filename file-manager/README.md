# git-drive Files (proof of concept)

A file manager with the Control Center's look: glass cards over the indigo gradient,
Liquid Glass on macOS 26, the same accent color (shared with the Control Center: picking it in
either app changes both) and the same app icon. It browses any folder; the git-drive mount is the first bookmark in the sidebar.

Status: proof of concept on the `poc/file-manager` branch. Its only changes on disk are the
context menu's (new folder, rename, paste, delete) and drag and drop's (move or copy). Nothing is ever overwritten.

## What it does

| Area | Behavior |
| --- | --- |
| Sidebar | Collapsible into a strip of icons (the button beside "Bookmarks", which stays at the top of the strip; Ctrl+Cmd+S or F9); there, resting the pointer on an icon names it in a popover beside it (a volume adds its free space, a missing bookmark says so), and moving on to the next icon names that one at once. **Bookmarks**: by default the drive, the home folder (by the user's name), Desktop, Documents and Downloads; drag one to reorder; add the folder in view from the menu of its empty space, by dropping folders between two bookmarks (the middle of a bookmark still drops into it), or with Add to Bookmarks in a folder's menu; remove one from its own menu. A bookmark follows a folder renamed here; one whose folder is gone shows dimmed. Saved in `~/.config/git-drive/files.json`. **Locations**: Computer, the mounted volumes and the Trash. |
| Tabs | As in Finder: Cmd+T (Linux: Ctrl+T) opens a tab at the folder in view, Cmd+W closes one, Ctrl+Tab and Cmd+Shift+[ ] go through them, Cmd+1 to 8 go to one and Cmd+9 to the last; Open in New Tab (menu of a folder, a bookmark, a Computer folder), Cmd+double-click or the middle button on a folder. The tab bar shows from two tabs on: pills (as the terminal's), each named after its folder (both, when split), with its full path in a popover on hover; the middle button closes one; items dropped on a tab go into its folder, and a drag resting on a tab opens it. |
| Split view | As in Dolphin, each tab can show its folders side by side, up to four: Cmd+/ (Linux Ctrl+/) or Split View in the window menu splits one pane into two and, with more, goes back to the pane with the keys; Open in Split View on a folder, a bookmark or a Computer folder adds a pane with that folder after the one with the keys, and the panes share the width evenly again; a fifth, or one that would leave a pane under 280 px, is refused with the reason. Each pane has its own folder, history, view, selection and search, names its folder on top and closes with its x (its room goes to its neighbors); a divider between each two drags (each pane keeps at least 280 px, each tab its own shares) and a double-click evens them all out. The pane with the keys is outlined in the accent and the other one is dimmed (a hover brings it a little closer); the toolbar, the sidebar, the preview and the keys act on it; Tab and Shift+Tab, or a click, move the keys through the panes. Dragging between the panes moves or copies as anywhere. A list in a narrow pane drops its Kind column, then Date Modified, so names keep their room. |
| Navigation | Back/forward history, Cmd+Up to the enclosing folder (above the root, Computer), clickable path (long paths collapse in the middle; the folder in view stays visible). The path turns into a text field (the pencil after it, Cmd+L or Linux Ctrl+L, Finder's Shift+Cmd+G, or "/" or "~" typed into the view): `~` is the home folder and a relative path starts at the folder in view; the folders of the typed parent are offered as the last name is typed (Tab completes, the arrows pick), Return goes there (a file: its folder, with it selected), a path that leads nowhere says so under the field, and Esc or a click elsewhere brings the breadcrumbs back. |
| Computer | The home's standard folders as large tiles (My Directories) and every mounted volume as a card with used and total space and a bar (amber above 80%, coral above 90%), as in the Deepin file manager. macOS: the system disk, browsable volumes in `/Volumes` and FUSE mounts in the home; Linux: `/`, disks in `/run/media`, `/media` and `/mnt`, a separate `/home` and FUSE mounts in the home, never a subvolume or bind mount of the system partition. A disk without a label is named by its size (`496 GB Volume`). The drive's card shows its repository against what the host accepts (`repo_usage` in the daemon's status: the object store, measured at boot and after every commit and pull; GitHub's 10 GB recommended maximum with a mark at the 5 GB it strongly recommends, GitLab.com's 10 GB, or `repo_quota_gb`; amber past the mark or 80%, coral past the limit), then the free space of the disk it lives on; a daemon that has not measured it yet shows the disk alone. |
| Trash | Linux: the freedesktop Trash (`~/.local/share/Trash`) with its items; Put Back returns an item where it was deleted from (remaking that folder, never replacing what is there now), Delete Immediately and Empty Trash ask first. macOS: `~/.Trash` is private to Finder unless the app has Full Disk Access; without it the view says so, opens the Trash in Finder, and its Allow Full Disk Access button opens that list in System Settings (no app can grant it to itself or ask with a prompt), with the steps and a link that shows the app in Finder to add it with +; with it, listing, Delete Immediately and Empty Trash work, and Put Back stays Finder's. Items dropped on the Trash in the sidebar move there. |
| Sort and group | The toolbar's menu: Group By None, Name, Kind, Date Modified, Date Created or Size (sections with a heading in the icon and list views and in search results; dates in Finder's sections: Today, Yesterday, Previous 7 Days, Previous 30 Days, the months of this year, then years); Sort By Name, Kind, Date Modified, Date Created or Size, ascending or descending. Folders stay first; the column view sorts but never groups. Both are remembered. |
| Icon view | A grid of large icons: folders in the accent gradient, documents as glass pages labelled with their extension, and thumbnails once drawn (images everywhere; on macOS also video, PDF, HEIC, TIFF, PSD and office documents, through Quick Look). Icon size slider in the status bar, from 48 to 192 px; arrow keys move through the grid. A folder shows what it holds over its icon, as Dolphin does: up to four of its own files that draw a thumbnail (pictures first, then videos, then documents, in natural order), as prints with a white frame, slightly turned (one from 48 px, two from 64, four from 88; a video gets a play mark from 96 px). Only folders on screen ask, once they have stayed there a moment and nothing scrolls; each asks the backend for its picks (`folder_preview`), which reads at most so many entries (names and types only), so many `stat`s and stops at a deadline, so a folder of 100,000 items costs the same as a small one. The scans and their pictures share the thumbnail queue, after the files' own thumbnails, two folders at a time. On the drive the rules are stricter: pictures only (up to 16 MiB), decoded in the app (Quick Look would write a PNG of decrypted content to `$TMPDIR`), one folder at a time, with fewer reads; a mount point, a network volume and other FUSE file systems get none. A folder leaving the screen withdraws what has not started and stops its scan; an operation, or the window coming back to the front (at most every 10 s), checks them again, the old ones staying until the new ones are drawn. Linux draws pictures only. A folder selected shows the same art in the preview panel (160 px) and in Quick Look (288 px), and so does the folder in view when nothing is selected; the picks already read for its tile are reused. |
| List view | Name, Date Modified, Size, Kind; click a header to sort; folders stay on top; natural order (`file2` before `file10`). |
| Column view | One column per folder from the drive, the home folder, a volume or the Trash (the nearest) down to the folder in view. Each column resizes by its right divider, as in Finder: drag one column, Option+drag every column (the new default), double-click to fit the longest name (Option: every column to its own). Widths are remembered per folder across sessions (the 200 most recently resized). |
| Preview | Images, video, audio and PDF (macOS) through the asset protocol, which reads only the byte ranges a player asks for; video with controls of the app's own in its glass (play, time, a seek bar in the accent, volume, full screen; in the narrow panel one slim line that drops what does not fit, fuller in Quick Look; hidden after 2 s without movement while playing; the buttons never take the keys, so Space still closes Quick Look); Markdown rendered (`marked`, sanitized by DOMPurify; local images from the file's folder, remote ones left as links so nothing is fetched, links opened in the browser, YAML front matter as a code block; a switch shows the source); JSON pretty-printed and colored from its own tokens (numbers kept as written), its lines drawn only where they show; 3D models (STL, 3MF with its colors, including Bambu Studio's, OBJ) drawn with three.js in the accent, turned by dragging, zoomed by the wheel, reset by a double-click, with the triangle count in Quick Look (three.js loads only when a model is shown). Each has a size limit in Settings, the panel's (1 MB by default) and Quick Look's (20 MB): above it Markdown and JSON show as text and a model offers Render Anyway; text and code (also files without an extension, detected by content) up to 256 KB, stopping where binary data starts (a self-extracting installer shows its script); images and videos always fit the preview's height; anything else shows its details. Open and Quick Look (the same as Space) under it. A panel of its own beside the view, the same in every view (in column view a folder open as the last column is summed up), a fixed width of at most a quarter of the window (20 rem); full window with Space (Quick Look). |
| Search | By name, case-insensitive, recursive from the folder in view, `.git` skipped, hidden items only when shown. Results stream in batches and are sorted like the list; a new search cancels the running one. Hovering a result (icon or list view) shows its full path, the searched folder dimmed. Limits: 1,000 results, 200,000 entries visited. |
| Context menu | Right click an item: New Folder and Compress first (`name.zip`, or `Archive.zip` for several), then Open (a folder: Open in New Tab and Open in Split View too); for a file, Open With (submenu: the apps that declare its type with their icons, the default first; listed by AppKit on macOS and GIO on Linux, loaded as the menu opens); then what its kind offers (Set Desktop Picture for a picture, on every screen on macOS and as GNOME's background on Linux; Extract Here for an archive); Cut, Copy, Paste, Rename, Move to Trash; a folder ends with Add to Bookmarks and Open in Terminal. Held while the menu opens (or pressed while it is open), Option (Alt) shows Finder's alternates: Always Open With (the app chosen becomes the default for that type), Copy Path (one per line) and Duplicate (`name copy`). Right click the empty space (in column view, a column's own, or past the last column for the folder in view): New Folder, Paste, Add to Bookmarks, Open in Terminal (with Option, Copy Path). Archives use the system's `bsdtar` (libarchive): extracting goes through a fresh folder, so a single item lands under its own free name and several go in a folder named after the archive, never merged into what is there; entries that climb out (`..`, absolute paths) or go through a link are refused; macOS's own metadata (`.DS_Store`, AppleDouble `._` files, `__MACOSX`) is left out and not restored, as Compress writes none (the drive is mounted with `noappledouble`, which refuses to create those files: one of them failed a whole extraction). A failure names the entry's own error (`Can't create ...`), not bsdtar's closing summary. Paste and New Folder act beside the item clicked (the folder in view, the column clicked, or where a search result lives). Paste copies, or moves what was cut (faded until then); a copy into its own folder is a duplicate (`name copy`, `name copy 2`), a name already taken elsewhere keeps both (`name 2`), and a folder never goes into itself. Moving to another volume copies, then removes the original once the copy is whole; a failed copy leaves nothing half done. Move to Trash (from the menu or the keyboard) asks first, Return confirming, and uses the system Trash; where there is none (the drive on Linux, a volume without a Trash) it asks before deleting for good instead. A drop on the sidebar's Trash does not ask. New Folder asks for the name (`untitled folder` by default). |
| Operations | Copies, moves, duplicates, moves to the Trash, deletes, Compress, Extract Here and emptying the Trash run side by side, each a card at the foot of the sidebar, against its bottom edge whatever the terminal's height: what it does and where to, a bar in the accent (bytes, else files; a sweep while it measures, or for an extraction, whose size comes last), how much and the time left. The x cancels: it stops at the next chunk or entry, what was done stays and the item under way is removed (a move leaves its original where it was). The eye opens its details live: from, to, the entry it is on, size, files, items, speed, time left, elapsed, and the error in full when it failed. A finished one shows Done for 4 seconds; a failed or cancelled one stays until dismissed. With the sidebar collapsed, a ring shows how far the ones under way are, and opens the details of all. |
| Rename | In place, as in Finder: the name becomes a field (wrapping under the icon in the icon view) with the name selected up to its extension. Enter, Tab or a click elsewhere saves, Esc cancels, an empty or unchanged name keeps the old one. A name already taken is refused with the reason below the field, which stays open to fix it; leaving it then drops the edit. A renamed folder keeps the window where it was (the open column, the history and the clipboard follow it); a name starting with a dot says the item is hidden now. Roots, the home folder and its standard folders, the volumes and the Trash keep their names. |
| Drag and drop | Drag an item onto a folder (a row, a tile, a column, the empty space of the folder in view, a bookmark or a volume), between two bookmarks (a new bookmark), onto the Trash, or out of the window to Finder, the desktop or Files: the drag is the system's own, so the destination decides as for a drag of its own. Within a volume it moves, to another it copies; Option copies and Cmd moves (Linux: Ctrl and Shift). Items dragged in from other apps land the same way. The folder under the pointer lights up; a folder never goes into itself, and dropping an item back where it is does nothing. Roots, the home folder and its standard folders, the volumes and the Trash are not dragged: trying shows the not-allowed cursor until the button is let go, the item shakes, and a message says why. |
| Edges | The listings (list, icons, columns, Computer) fade softly (to a quarter; on the light theme to 60% over 8 px, which would otherwise read as a glow) over their top and bottom 12 px instead of being cut where they scroll under the pane's header and its status bar; their padding keeps the first and last rows clear of it at rest, and a drop's outline stays whole. |
| Multiple selection | As in Finder: Cmd+click (Linux: Ctrl+click) adds or takes out an item; Shift+click selects the range from the last item clicked in the list and column views, and adds in the icon view; Shift+arrows extend; Cmd+A selects everything; dragging on the empty space draws a selection rectangle (with Cmd or Shift it adds). A press on one of several selected items keeps them, so they can be dragged together; the release without a drag narrows to that item. In column view a selection lives in one column. Copy, cut, delete, drag and the context menu act on the whole selection (rename takes one item); open opens each file; the preview and the status bar summarize it (`3 items`, `3 of 20 selected`). |
| Terminal | A panel under the folders, as in VS Code, in the app's glass: tabs of the user's login shell (`$SHELL -l`: the PATH and environment of a terminal opened from scratch), each starting in the folder in view and named after the shell's current folder; + opens another, the folder button types a `cd` to the folder in view. xterm.js draws it with its WebGL renderer (box drawing and powerline symbols fill the whole cell, so a tmux or prompt bar stays whole; the DOM renderer when WebGL is missing), Unicode 11 character widths as tmux counts them (JetBrains Mono, from its Nerd Font build when installed, so prompt themes such as Powerlevel10k show their icons, with other Nerd Fonts after it; the 16 colors in the app's palette, the cursor and selection in the accent) over a pseudo-terminal of the backend (`portable-pty`, output streamed as raw bytes). A tab whose shell runs `ssh` in front (the terminal's foreground process group, read from the system) is named after the server, as typed (`maestro`, `user@host`, `-l` folded in), with a server icon; its tooltip adds the title the remote side set. A tab splits into panes as in iTerm: side by side (Cmd+D, Linux Ctrl+Shift+E) or one above the other (Cmd+Shift+D, Linux Ctrl+Shift+O), as often as wanted (a tree of splits), with dividers that drag; the new pane starts in the folder of the one it split; Cmd+Option+arrows (Linux Alt+arrows) move between panes, the panes without the keys are dimmed, and Cmd+W closes the pane in front (the tab with its last pane). Each pane's terminal lives in its own element, moved when the tree changes, so a split never restarts a shell. Each pane of a split has a close button in its top right corner, barely visible until the pointer is on it; it asks first, naming what still runs in the pane (an SSH session, a command). Each pane refits from its own size (a divider dragged, a split, the window), and is drawn again in full when the panel shows again. A full-screen program (nvim, htop, tmux: what draws on the alternate screen), or a program that stays in front on the normal screen (Claude Code draws its interface there, an SSH session, a server's log: seen in front by two status reads in a row, about a second and a half, so a quick `ls` never repaints the pane), gets its background under the whole pane, its padding and the edge the grid leaves over included: the color most of its cells carry when it paints a fifth of the screen or more (an editor's colorscheme), else an opaque dark one, so a tmux whose panes keep the default background reads as one surface; the panel's header keeps its glass, and the glass comes back when the program ends. On that screen a clear erases in place (on the normal screen it scrolls what was there into the scrollback). A tab is named after the server over SSH, else the program in front (`nvim`, with its folder in the tooltip), else the shell's folder. The panel stays dark on the light theme (its colors, and what remote shells and tmux draw, are made for a dark ground). The maximize button in its header (or a double-click on the header's empty part) puts it over the folders: it takes their room and the folder tabs', and the sidebar and the toolbar stay; restore brings them back, and so does going somewhere (a bookmark, the toolbar, a path followed from the output); hidden and shown again, it comes back maximized. Cmd+J (Linux: Ctrl+J), as VS Code's panel, shows or hides it, also from inside it (hiding keeps the shells; closing a tab, or its shell exiting, ends it, and the last one hides the panel); its top edge drags to resize, up to half the room it shares with the folders, and the height is remembered. A resize reaches the shell once it settles (one SIGWINCH per drag); when the width changed and the shell sits at its prompt (it leads the terminal's foreground process group), the shell redraws its screen with Ctrl+L, so prompts wrapped by the reflow and copies of a two-line prompt do not pile up; what was on the screen goes to the scrollback. Open in Terminal (menu of a folder or the empty space) opens a tab there; items dropped on it are typed in as paths, quoted where needed; Cmd+click (Ctrl+click) on a web link opens the browser, and on a path in the output (absolute, `~/`, or relative to the shell's folder; `file:line` too) the app goes there or selects the file. The status bar's terminal button and the window menu's Show Terminal do the same as Cmd+J. |
| Window menu | The three dots at the top right, lined up with the folders' container: New Tab, New Folder, Split View, Show Hidden Files, Show Terminal, Show Preview, Show Status Bar, Settings and About (the toolbar keeps only navigation, the views, Sort and group, and search). |
| Languages | English and Brazilian Portuguese, the system's language by default (the first of its preferred languages the app has), or one chosen in Settings, applied at once without a restart. Everything the window shows follows it, the backend's messages too (errors of the file system, the operations, archives, metadata), and so do dates, numbers and sizes (`1,5 GB` in Portuguese). Plurals by the language's rules. Names the app gives files follow it too (`budget copy.xlsx` or `budget cópia.xlsx`, `Archive.zip` or `Arquivo.zip`). Key names (Cmd, Ctrl, Shift), units and proper names stay as they are. |
| Settings | A dialog over the window (dialogs over the window are opaque enough for small text over the blurred files), as Quick Look shows a file (Cmd+, or the window menu; Esc, Cmd+, or a click outside close it): a search field filters the settings as one types (every word, accents ignored), each section showing only what matched. General: the language (System, English, Português (Brasil)). Appearance: the theme (System, Light or Dark: the light one is the same glass, cards and accent over a pale surface, with the native glass and the terminal's colors following; System changes with the system's own), the accent color, with the Control Center's picker, one preference for both apps (`~/.config/git-drive/control-center.json`; a change made in the Control Center shows here when the window comes back to the front). Icon view: the previews on folders, and apart those on the drive's folders. Preview: the largest Markdown, JSON or 3D model the panel (250 KB to 20 MB, 1 MB by default) and Quick Look (1 to 100 MB, 20 MB by default) render. Photos: the map of where a photo was taken (on by default; it loads OpenStreetMap's tiles, whose servers see the area shown; off, only the coordinates). Window: the status bar under each pane (off, the item count, the icon size slider and the terminal button go; Cmd+= and Cmd+-, Cmd+J and the window menu still do their work), the preview panel, the sidebar's labels and the terminal. |
| Properties | Cmd+I (Linux: Ctrl+I) or Properties at the end of a menu (of items, or of the empty space for the folder in view), in a dialog over the window. General: kind, size (a folder's or several items' measured in the background, stopped when the dialog closes), on disk, where (copy the path), link target, created, modified, opened, owner and group by name, inode. Permissions: owner, group and everyone by read, write and execute, the special bits, the octal mode (typed or shown with `ls -l`'s letters); several items show a mixed box where they differ and only what is touched changes; folders can apply to what they hold; only the owner changes them, and in the drive they last while it is mounted (Git does not keep them). Extended attributes by name and size; a download's quarantine can be removed (macOS). For a picture: the description (title, description, keywords as chips, creator, copyright, stars, date taken with its time zone), saved together; the camera, the exposure and the image (size in megapixels, format, orientation, color space); the location with a map (OpenStreetMap; a larger one with zoom and drag; Apple Maps or OpenStreetMap in the browser), Remove Location and Remove All Metadata (the orientation and the color profile stay), each asking first. Several pictures take the same creator, copyright, added keywords and rating, and the privacy actions, as one operation in the sidebar. JPEG and PNG are rewritten without re-encoding (the XMP merged, the EXIF changed in place); HEIC through ImageIO on macOS; other formats (raw, TIFF, WebP, HEIC on Linux) get an XMP sidecar, `name.ext.xmp`. |
| About | The window menu's last item: the app's version, platform and processor, window effect and Tauri version, with links to the source code, the releases, the issues and the license. |
| Long folders | The list, the icons and each column draw only the rows on screen plus 480 px above and below (a folder of 5,000 items draws 30 to 100), between spacers that keep the scroll height whole; rows have fixed heights (a tile is sized for two lines of name), the keyboard scrolls to the focus by its place, and the selection rectangle finds the items it crosses from their places, also the ones not drawn. |
| Other | Show or hide hidden files (dot-files and macOS hidden flags), open in the default app, reveal in the system file manager. |

## Build and run

```bash
cd file-manager
npm install
npm run tauri build -- --bundles app    # macOS; on Linux: npm run tauri build -- --no-bundle
../target/release/git-drive-files                  # opens at the drive (or Home)
../target/release/git-drive-files --path ~/Pictures
cargo test --release -p git-drive-files            # file model tests
```

To hand the app to someone else on macOS, `npm run package:mac` (`scripts/package-macos.sh`)
builds it and makes `target/release/bundle/dmg/git-drive-Files-<version>-arm64.dmg`: the app
beside a link to Applications, in a compressed disk image made by `hdiutil` (no Finder scripting,
so nothing opens on screen), both signed. Without Apple credentials the signature is ad hoc and the
first open on another Mac goes through System Settings, Privacy & Security, Open Anyway. With
`APPLE_SIGNING_IDENTITY` (a Developer ID Application certificate in the keychain) and `APPLE_ID`,
`APPLE_PASSWORD` (app-specific) and `APPLE_TEAM_ID`, the same script signs with the Developer ID,
has Apple notarize the app and the image, and staples the tickets, so it opens with no warning.
`UNIVERSAL=1` builds for Apple silicon and Intel (after `rustup target add x86_64-apple-darwin`).

Needs Node 20+ and, on Linux, `webkit2gtk-4.1`, like the Control Center. The app links only
`git-drive-state` (the daemon's status, paths and disk figures; no FUSE, no Git), so it opens on
a Mac without macFUSE or Homebrew's OpenSSL; the drive shows where the daemon's status is. The crate is a
workspace member outside the default members, so root `cargo` commands never build it.

## How it is built

| Part | Role |
| --- | --- |
| `src-tauri/src/fsmodel.rs` | The filesystem model, tested without a webview: `list_dir` (natural order, folders first, hidden detection), `classify` (preview kind by extension, then content: Markdown, JSON and 3D models among them), `read_text` (bounded, 256 KB unless the window asks for more within a preview limit; cut on a character boundary), `search` (breadth-first, cancellable, reports each match). |

## Known limitations

- Two languages. Text from outside tools (the first error line of `bsdtar`, a macOS error's
  description, `gsettings`) is quoted as the tool gives it inside a translated sentence. Folder
  names on disk are their own (macOS's localized names of Desktop or Documents are not shown).
- 3D: an OBJ's `.mtl` materials are ignored; a 3MF whose parts reuse object ids across their files
  (some production-extension files) cannot be drawn. No 3D thumbnails in the icon view yet.
- Folder previews come from the folder's own files only (a folder holding only folders stays
  plain), and do not change on hover as Dolphin's can. Video and PDF previews need Quick Look,
  so Linux and the drive draw pictures only.

- The clipboard is the app's own: Finder and the Linux file managers do not see what Copy put
  aside, and Paste does not take files copied there. No undo, no progress or cancel for a long
  copy, and no Replace: a name already taken always keeps both.
- Bookmarks are this app's own: Finder's Favorites and the GTK bookmarks are neither read nor
  written. A bookmark follows a rename made here; a folder moved, or renamed elsewhere, leaves
  it dimmed until it is removed.
- The app is signed ad hoc (`signingIdentity: "-"`: the whole bundle sealed, hardened runtime),
  not with a Developer ID, and not notarized. On another Mac, a copy that arrived by download
  (quarantined) opens only after System Settings, Privacy & Security, Open Anyway, or
  `xattr -dr com.apple.quarantine "git-drive Files.app"`. Before this setting the build sealed
  only the executable, and such a copy was reported as damaged. A Developer ID and notarization
  (Apple Developer Program) would open it with no warning. macOS also ties a Full Disk Access
  grant to the binary's hash: every new build has to be turned on again in the list. The build
  is for Apple silicon only (arm64); an Intel Mac needs `--target universal-apple-darwin`.
- Compress and Extract Here need `bsdtar` (always on macOS; on Linux in the libarchive package,
  installed with pacman on Arch); without it they are not in the menu. Set Desktop Picture on
  Linux knows GNOME only. Open With is for files (folders open here).
- Volumes have no Eject, and the list is read again every 10 s and when the window comes back to
  the front. On Linux the Trash is the home one only: items deleted on another disk go to its
  own `.Trash-<uid>`, which this view does not show. On macOS, Put Back is Finder's (its record
  of where an item came from is its own).
- Folders do not open while a drag hovers them (no spring-loaded folders). The selection
  rectangle starts on the empty space only (in the list view, below the rows: a row is a drag
  handle), and there is no "Rename N Items" for a multiple selection. Whether Finder or Files moved or
  copied a dragged item is not reported; the window looks again shortly after the drop.
- Rename does not ask before changing an extension or before a name that starts with a dot
  (Finder does); the item is renamed and, when hidden items are off, a message says it is hidden
  now. A click on the name of the selected item does not start a rename: Enter (F2) or the menu.
- On Linux, deleting from the drive is permanent after a confirmation (the item stays in the
  drive's Git history). The standard per-volume Trash, `.Trash-<uid>` at the drive's root, would
  be committed and pushed like any folder: the daemon treats only macOS's `.Trashes` as
  ephemeral. On macOS the drive's Trash is Finder's: in memory until the mount restarts.

- PDF preview needs the macOS webview; on Linux a PDF shows its details and an Open button.
- Thumbnails on Linux cover raster images only (PNG, JPEG, GIF, WebP, BMP); video, PDF and
  documents keep their icon. Thumbnails live in memory for the session (nothing is written to
  disk, so a drive's content never lands outside it in clear): a relaunch draws them again.
- Search matches names only and has no index; a first search over a large drive takes seconds
  (results appear as they are found).
- The asset protocol may read any file of the user (scope `**`): acceptable for a local POC,
  to be narrowed before it ships.
- The git-drive FUSE mount reports placeholder free-space numbers (no `statfs`), so the Computer
  view measures the drive on the repository's volume; Finder shows the placeholder.
- On Linux, WebKitGTK's helper process sometimes crashes while the window closes (as in the
  Control Center); no effect on the app.
